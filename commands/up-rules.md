精煉專案的規則文件：排除陳冗字句，但**不流失任何指令語意**，使未來每次 AI 讀取都能快速且完整理解。

壓縮的對象是**冗詞、重複敘述、裝飾性說明**，絕非具體規則、約束條件或消歧義範例。

## 目標檔案（存在哪個就處理哪個，缺的略過）

- `CLAUDE.md`（專案根目錄）
- `./.claude/CLAUDE.md`
- `./.claude/rules/*.md`

僅處理上述三種路徑。**不要**擴及 `skills/`、`commands/`、`settings.json` 或其他檔案。

## 執行流程

### 1. 蒐集脈絡

- 用 glob 找出實際存在的目標檔案，完整讀取每一個。
- `git log --oneline -15` 與 `git diff` 檢視近期改動與開發方向。**這一步有明確任務**：找出近期新增的規則是否與既有內容**重疊、重複或矛盾**——這正是最該合併或刪除的部分。把找到的重疊點餵進後續壓縮，而非只是看過。

### 2. 建立指令清單（壓縮前）

逐檔提取一份**明確的指令清單**——每一條獨立的規則、約束、禁止事項、格式要求各列一項。這份清單是後續驗證不流失的基準，必須先建立、後改寫。

### 3. 逐檔精煉

依下方「精煉原則」改寫每個檔案。改寫時：

- 合併第 1 步發現的重疊／重複規則。
- 壓縮冗詞與裝飾性敘述。
- 維持有助 AI 快速掃描的結構（標題、條列、表格、程式碼區塊）。

### 4. 驗證未流失（壓縮後）

逐項比對第 2 步的指令清單：確認**每一條**指令在改寫後的內容中仍然存在（語意等價即可，不要求字句相同）。

⚠️ 由同一次改寫順手「自我感覺沒漏」不算驗證——必須拿清單逐條核對，否則會悄悄刪掉邊角規則卻回報成功。

### 5. 寫入並回報

直接用 Edit/Write 寫入檔案（**不要**自動 git commit，交由 `/now-push` 或使用者決定）。回報：

- 每檔的指令清單，逐條標記「保留 ✓」。
- 每檔行數／字數前→後對照與壓縮比（**作為觀察值陳述，不是追求的目標**）。
- 主要刪改點（合併了什麼、刪了什麼冗詞）。

## 精煉原則

| 移除／壓縮                             | 完整保留                                   |
| -------------------------------------- | ------------------------------------------ |
| 填充詞、贅語、模糊修飾                 | 每一條獨立的規則與約束條件                 |
| 重複或重疊的規則（合併為一）           | 禁止事項與例外情況                         |
| 對顯而易見之事的過度說明               | 消歧義用的 ✅／❌ 對照範例                   |
| 裝飾性開場白、結語                     | 精確的術語與專有名詞                       |
| 同義反覆的句子                         | 有助 AI 掃描的標題／條列／表格結構         |

### 逐字保留（一字不改，byte-for-byte）

以下內容**禁止改寫、改寫即降低正確性**：

- 程式碼區塊與 fenced block 內的所有內容
- 確切的指令字串（如 `git commit -m ...`）
- 格式範本／模板（如 commit message 結構、trailer 如 `Co-Authored-By: ...`）
- 消歧義用的正反範例（✅ 正確 ／ ❌ 錯誤）

只壓縮這些區塊**周圍的散文敘述**，區塊本身不動。

## 禁止事項

- 不新增任何原本沒有的規則或功能。
- 不因某條規則「太長」就刪掉它——只刪冗詞，不刪語意。
- 不為了壓縮比而過度刪減；寧可保守也不流失指令。
- 不改動目標檔案以外的任何檔案，不自動 commit。
